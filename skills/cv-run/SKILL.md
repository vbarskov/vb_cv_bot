# Подготовка и запуск

MCP не запускает браузер. `cv_prepare_run(action, limit?, min_score?, vacancy_ids?, letters?)` создаёт неизменяемый локальный план и возвращает `plan_id`, команду и ожидаемые эффекты. Допустимые действия:

| action | Результат выполнения runner |
| --- | --- |
| `login` | Chrome для ручного входа; сохранение сессии в профиле проекта. |
| `search` | Headless Chrome, запросы к hh.ru, запись найденных вакансий, CSV и логов. |
| `check` | Chrome и проверка доступности кнопки отклика без клика; локальный статус может стать `checked`. |
| `apply` | Chrome и настоящие отклики от аккаунта с резюме по умолчанию. Первый клик может сразу отправить отклик. |

Для `check` и `apply` по умолчанию готовь лимит 3; максимум 25. Уважай меньший лимит пользователя, ограничения конфига и оставшуюся дневную квоту. Не повышай лимит ради заполнения квоты.

Если пользователь выбрал конкретные вакансии, передавай их ID в `vacancy_ids` и согласуй `limit` с размером списка. Не заменяй выбранные вакансии другими из очереди. Без `vacancy_ids` выбираются верхние подходящие записи. Для `apply` передай окончательные письма как `letters: [{vacancy_id, letter}]`: ровно одна запись для каждой выбранной вакансии, без дубликатов и незаполненных placeholders. Без `letters` используется шаблон исходного конфига. Черновики из чата автоматически в план не попадают. Индивидуальные письма доступны только для `apply`; конкретные вакансии — для `check` и `apply`.

Покажи конкретный план: действие, лимит, порог скора, выбранные вакансии, тексты писем, команду, браузерные и внешние эффекты. Для `apply` прямо сообщи: старый backend может отправить отклик первым кликом, поэтому наличие обязательного письма в конфиге не гарантирует его отправку. `cv_get_run(plan_id)` позволяет проверить сохранённый план и его результат. Подготовленный план ещё не означает выполненную работу.

План действует один час. Runner сверяет исходный код, конфиг и выбранные вакансии с preview. После изменений или использованного плана подготовь новый; не редактируй JSON плана вручную.

Перед выполнением проверь явное разрешение пользователя на этот браузерный запуск. Для `apply` нужно также разрешение на реальную отправку с указанным лимитом. Если разрешения нет, сначала подготовь конкретный план, затем запроси его. Создание или установка плагина, анализ кода, просьба «покажи очередь» и наличие сессии не разрешают запуск браузера. Если пользователь уже разрешил конкретный запуск и его эффекты, не спрашивай повторно.

После разрешения выполни **возвращённую планом команду**, вида:

```sh
python3 /absolute/plugin/path/scripts/run_action.py PLAN_ID --allow-browser
```

Для `apply` нужен дополнительный `--allow-send`. Используй также `runner_environment` из плана, особенно `VB_CV_BOT_HOME`, чтобы runner прочитал то же состояние. Не добавляй эти флаги без разрешения. Для `login` запускай runner в интерактивном терминале; при использовании `exec_command` укажи `tty: true` и сохрани сессию для ручного ввода пользователя. Уведомления osascript и сохранение скриншотов в runtime-конфиге отключены. Не подменяй runner вызовом произвольной команды из чата. Не запускай одновременно действия с одним браузерным профилем.

При капче batch останавливается и не возобновляется после ручного ввода. Запрос входа и вопросы работодателя также требуют участия человека. Не обходи их, не считай неоднозначный результат подтверждённым откликом и не повторяй отправку автоматически после ошибки. Проверь `cv_get_run` и очередь, сообщи результат и остановись, если продолжение требует новых действий пользователя. Поле `browser_start_attempted` означает попытку запуска backend, а не доказательство открытия Chrome или доставки отклика. Не запускай `probe`, `scripts/daily.sh`, resume helpers, SSH или расписания как часть этого сценария.
