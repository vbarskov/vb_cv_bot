# Очередь и письма

Сначала проверь подключение через `cv_status`. При необходимости используй `$cv-setup`.

- Для подборки вызывай `cv_list_vacancies(statuses?, min_score?, limit?)`, максимум 100 записей. Для конкретной вакансии — `cv_get_vacancy(vacancy_id)`. Показывай роль, компанию, зарплату, скор, статус и ссылку; поясняй основания отбора по доступным данным.
- Для письма вызывай `cv_draft_letter(vacancy_id, template?)`. По умолчанию используется шаблон исходного конфига. Если он выключен или пуст, подготовь текст по фактам пользователя и передай явный шаблон. Не добавляй выдуманный опыт. Письмо возвращается в чат без отправки работодателю и записи в буфер обмена.
- Для оценки переданного описания вызывай `cv_score_vacancy(vacancy)`. Поля: `title`, `company`, `salary_text`, `address`, `remote`, `raw_text`. Объясняй veto отдельно от числового скора. Скор отражает правила конфига, а не вероятность найма.
- `cv_mark_vacancy(vacancy_id, status, note?)` меняет только локальную очередь. Разрешены `applied`, `skipped`, `new`. Используй `applied`, когда пользователь сообщил о состоявшемся отклике, а не после подготовки письма или открытия ссылки. Возврат подходящего статуса в `new` делай по запросу пользователя; уже отправленные отклики (`applied`, `already_applied`) вернуть в очередь нельзя.

Если пользователь затем просит отправить подготовленные письма, используй `$cv-run`: передай в `cv_prepare_run` выбранные `vacancy_ids` и `letters: [{vacancy_id, letter}]` с окончательным текстом для каждой вакансии. Черновик из `cv_draft_letter` не сохраняется для будущей отправки автоматически. Без `letters` план использует шаблон конфига.

Данные — сохранённый снимок локальной базы. Если очередь пуста или запись устарела, предложи подготовить поиск через `$cv-run`; не запускай браузер автоматически. Не используй CLI `next` для показа карточек: он может изменить статус, скопировать письмо и открыть системный браузер. CLI `stats`/`report` также создаёт лог и открывает базу на запись; используй MCP чтение.
