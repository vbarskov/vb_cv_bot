# Планы и результаты действий

## Разработка пакета

7 ноября 2026: исследован существующий `cv_bot`; выбран локальный адаптер, чтобы не включать персональные данные и браузерную сессию в пакет. Добавлены MCP-инструменты, транзакционные ручные отметки, preview точных вакансий и писем, отдельный runner, манифесты и три skills. Независимый просмотр выявил и помог исправить синтаксическую ошибку bridge, передачу индивидуальных писем, выбор по ID и требования интерактивного входа. Статический разбор Python и JSON выполнен.

По разрешению пользователя выполнен один запуск 45 локальных тестов: 44 прошли, один выявил ошибку сравнения тестовых путей `/var` и `/private/var` на macOS. В тестовой среде исправлены нормализация путей и закрытие временных SQLite-соединений. После отдельного разрешения повторная локальная проверка прошла: 45 из 45 тестов, без браузера и сети.

## Состояние запусков

Подключение и подготовленные планы хранятся в `VB_CV_BOT_HOME` (по умолчанию `~/.local/share/vb-cv-bot`), отдельно от устанавливаемого пакета:

- `connection.json` — путь исходного проекта и конфига;
- `plans/<plan_id>.json` — preview и состояние конкретного запуска.

Проверяйте конкретный план через `cv_get_run(plan_id)`. Отдельного фонового сборщика журналов нет.

`cv_prepare_run` фиксирует действие, аргументы, команду, окружение, выбранные вакансии и письма. Для точного выбора передаются `vacancy_ids`; для окончательных писем — `letters: [{vacancy_id, letter}]`, по одной записи на выбранную вакансию. План истекает через один час. Runner сверяет fingerprint исходного кода, конфига и выбранных записей; изменения требуют нового preview. Изменение лимита, порога, писем или действия также требует нового плана. Сам план не является разрешением на запуск и не свидетельствует о том, что действие состоялось.

| Стадия | Что можно утверждать |
| --- | --- |
| `prepared` | Команда и эффекты доступны для проверки; браузер ещё не запущен. |
| `running` | Запущен CLI исходного проекта в разрешённом объёме; результат ещё не известен. |
| `completed` | Доступен результат локального процесса. Итог откликов проверяется по статусам базы и выводу бота. |
| `failed` / `interrupted` | Продолжение и факт отправки могут требовать ручной проверки; автоматическая повторная отправка не выполняется. |

Для выполнения runner требует `--allow-browser`; для действия `apply` также `--allow-send`. Отсутствие флага останавливает запуск. Используйте `runner_environment` из плана, чтобы прочитать тот же каталог состояния. Для ручного ввода при `login` нужен интерактивный терминал (`exec_command` с `tty: true`). Капча останавливает прогон без автоматического возобновления. Runtime-конфиг отключает уведомления osascript и скриншоты.

`browser_start_attempted` отражает попытку runner запустить backend. Даже значение `true` не доказывает, что Chrome успешно открылся: запуск может завершиться до браузерного действия. Факт отправки оценивается по состоянию конкретной вакансии и данным hh.ru.

Записи запуска могут содержать пути, аргументы и диагностические сведения. История вакансий и откликов остаётся в SQLite исходного `cv_bot`, а подробный лог и debug-файлы — в его каталоге данных. Не считайте успешный код завершения CLI доказательством отправки каждой вакансии: обработанные записи могут быть пропущены, закрыты или требовать ручного ответа.

Если процесс оборвался после внешнего действия, сначала проверьте `cv_get_run`, запись вакансии и состояние на hh.ru в разрешённом браузерном сценарии. Не повторяйте `apply` только ради получения успешного результата процесса. Удаление локального плана или возврат вакансии в `new` не отменяют отправленный отклик.
